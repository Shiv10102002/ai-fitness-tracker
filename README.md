# 🏋️ AI Fitness Tracker — Microservices

A full-stack fitness tracking application built with a **microservices architecture**. Users can log workouts and instantly receive **AI-powered analysis and recommendations** generated by Google Gemini. Authentication is handled by **Keycloak** using the OAuth2 PKCE flow, and activity events are streamed asynchronously via **Apache Kafka**.

## Features

### 🔐 Authentication & User Management
- **OAuth2 PKCE login** via Keycloak — no passwords stored in the app
- **Automatic user sync**: on first login, the gateway reads the JWT and silently registers the user in the User Service
- Users can log in and log out from the React frontend

### 🏃 Activity Tracking
Log fitness activities with the following details:
- **Activity types**: `RUNNING`, `WALKING`, `CYCLING`, `SWIMMING`, `WEIGHT_TRAINING`, `YOGA`, `HIIT`, `CARDIO`, `STRETCHING`, `OTHER`
- Duration (minutes)
- Calories burned
- Start time and additional custom metrics

### 🤖 AI-Powered Recommendations (Google Gemini)
After every logged activity, an event is published to Kafka. The AI Service consumes it and calls the **Google Gemini API** to generate a structured recommendation containing:
- **Overall analysis** — performance summary
- **Pace analysis** — effort and speed feedback
- **Heart rate analysis** — intensity zone evaluation
- **Calories analysis** — energy expenditure review
- **Improvement areas** — targeted advice per metric
- **Next workout suggestions** — recommended follow-up exercises
- **Safety guidelines** — injury prevention tips

If the AI call fails for any reason, a sensible **fallback recommendation** is saved automatically so no activity is ever left without a response.

### 📊 Activity History & Detail View
- View a full list of all past activities
- Click any activity to see its details alongside the full AI recommendation

## API Reference

All requests go through the **Gateway** at `http://localhost:8080`. Every endpoint (except `/api/users/register`) requires a valid Keycloak JWT in the `Authorization: Bearer <token>` header.

### User Service — `/api/users`

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| `POST` | `/api/users/register` | ❌ Public | Register a new user |
| `GET` | `/api/users/{userId}` | ✅ Required | Get user profile |
| `GET` | `/api/users/{userId}/validate` | ✅ Required | Check if user exists by Keycloak ID |

**Register request body:**
```json
{
  "email": "user@example.com",
  "password": "yourpassword",
  "firstName": "John",
  "lastName": "Doe",
  "keyCloakId": "keycloak-uuid"
}
```

---

### Activity Service — `/api/activities`

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| `POST` | `/api/activities` | ✅ Required | Log a new activity |
| `GET` | `/api/activities` | ✅ Required | Get all activities for the logged-in user |

**Log activity request body:**
```json
{
  "type": "RUNNING",
  "duration": 30,
  "caloriesBurned": 300,
  "startTime": "2024-01-15T07:00:00",
  "additionalMetrics": {
    "distanceKm": 5.2,
    "avgHeartRate": 145
  }
}
```

> The `X-User-ID` header is injected automatically by the Gateway from the JWT — you do not need to set it manually.

---

### AI Service — `/api/recommendation`

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| `GET` | `/api/recommendation/user/{userId}` | ✅ Required | Get all recommendations for a user |
| `GET` | `/api/recommendation/activity/{activityId}` | ✅ Required | Get recommendation for a specific activity |

**Recommendation response:**
```json
{
  "id": "...",
  "activityId": "...",
  "userId": "...",
  "activityType": "RUNNING",
  "recommendation": "Overall: Great session...\n\nPace: ...\n\nHeart Rate: ...\n\nCalories Burned: ...",
  "improvements": [
    "Pace: Aim to increase your average pace by 10%"
  ],
  "suggestions": [
    "Interval Training: Alternate between fast and slow running for 20 minutes"
  ],
  "safety": [
    "Always warm up before exercise",
    "Stay hydrated throughout your workout"
  ],
  "createdAt": "2024-01-15T07:35:00"
}
```

## Getting Started

### 1. Clone the Repository

```bash
git clone https://github.com/Shiv10102002/ai-fitness-tracker.git
cd ai-fitness-tracker
```

### 2. Set Up Infrastructure

#### Kafka + Zookeeper (Docker)
```bash
# Start Zookeeper
docker run -d --name zookeeper \
  -e ZOOKEEPER_CLIENT_PORT=2181 \
  -p 2181:2181 \
  confluentinc/cp-zookeeper:latest

# Start Kafka
docker run -d --name kafka \
  -e KAFKA_BROKER_ID=1 \
  -e KAFKA_ZOOKEEPER_CONNECT=host.docker.internal:2181 \
  -e KAFKA_ADVERTISED_LISTENERS=PLAINTEXT://localhost:9092 \
  -e KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR=1 \
  -p 9092:9092 \
  confluentinc/cp-kafka:latest
```

#### Keycloak (Docker)
```bash
docker run -d --name keycloak \
  -e KEYCLOAK_ADMIN=admin \
  -e KEYCLOAK_ADMIN_PASSWORD=admin \
  -p 8181:8080 \
  quay.io/keycloak/keycloak:latest start-dev
```

Then open `http://localhost:8181` and:
1. Create a realm named **`fitness-app`**
2. Create a client named **`oauth2-pkce-client`** with:
   - Client authentication: **OFF**
   - Standard flow: **ON**
   - Valid redirect URIs: `http://localhost:5173/*`
   - Web origins: `http://localhost:5173`
3. Create a test user inside the realm

#### PostgreSQL
```bash
# Create the database for User Service
psql -U postgres -c "CREATE DATABASE \"fitness-micro-user\";"
```

#### MongoDB
MongoDB can be run locally (`mongod`) or via Docker:
```bash
docker run -d --name mongodb -p 27017:27017 mongo:latest
```

### 3. Configure Secrets

The Config Server reads property files from `configServer/src/main/resources/config/`. These files contain placeholders — fill them in with your real values before starting:

**`configServer/src/main/resources/config/ai-service.properties`**
```properties
gemini.api.key=YOUR_GEMINI_API_KEY
```
Get your key from [Google AI Studio](https://aistudio.google.com/apikey).

**`configServer/src/main/resources/config/user-service.properties`**
```properties
spring.datasource.password=YOUR_POSTGRES_PASSWORD
```

> ⚠️ Never commit real keys to git. These files are listed in `.gitignore`.

### 4. Start Backend Services (in order)

Each service is a standalone Maven project. Open a separate terminal for each:

```bash
# 1. Eureka Server
cd eureka && mvn spring-boot:run

# 2. Config Server
cd configServer && mvn spring-boot:run

# 3. User Service
cd userservice && mvn spring-boot:run

# 4. Activity Service
cd activityservice && mvn spring-boot:run

# 5. AI Service
cd aiservice && mvn spring-boot:run

# 6. Gateway (start last)
cd gateway && mvn spring-boot:run
```

Verify all services are registered at: `http://localhost:8761`

### 5. Start the Frontend

```bash
cd fitness-frontend
npm install
npm run dev
```

Open `http://localhost:5173` in your browser.

### 6. Use the App

1. Click **LOGIN** — you'll be redirected to Keycloak
2. Log in with your Keycloak test user
3. You're redirected back to the app and auto-registered in the User Service
4. **Log an activity** using the form (type, duration, calories)
5. The activity is saved and a Kafka event triggers AI analysis in the background
6. Click any activity in the list to view its **AI recommendation**

## Environment Configuration

All backend configuration is managed centrally by the **Config Server**. Each service fetches its config on startup from:

```
configServer/src/main/resources/config/<service-name>.properties
```

| Config File | Service | Key Settings |
|---|---|---|
| `ai-service.properties` | AI Service | Gemini API URL & key, Kafka consumer config, MongoDB URI |
| `activity-service.properties` | Activity Service | MongoDB URI, Kafka producer config |
| `user-service.properties` | User Service | PostgreSQL URL, username, password |

Individual services only set `spring.application.name` and the config server URL in their own `application.properties`.
